# AI Trust
## When did I trust the AI?
- When it reviewed my code and identified specific purity and correctness issues with line numbers
- When it evaluated weaknesses in my update_game_state function with concrete examples
## When did I stop trusting it?
When it gave long step-by-step instructions that felt generic and unhelpful and didn't actually include step-by-step instructions.
## What signals or situations or patterns indicated low reliability?
Instructions that felt padded or repetitive rather than focused on the actual problem

# What I Learned
## What did you learn about software development?
The importance of function purity for testability and correctness
## What did you learn about using AI tools?
Be specific about what you want so the AI doesn't get off track
## When should you trust AI? When should you double-check it?
- Trust: for code review, identifying bugs, test case generation, and documentation
- Double-check: step-by-step instructions, guidance, and architectural decisions

# Reflection
## Did AI make you faster? Why or why not?
Mixed. The code review was fast and valuable. But the step-by-step guidance added time rather than saved it.
## Did you feel in control of the code?
Yes. I asked specific questions about what was wrong and why, which let me understand and fix issues myself. The Socratic approach in steps felt controlling, but direct reviews put me back in control.
## Would you use AI the same way next time? What would you change?
Ask for code reviews first, not step-by-step guidance. Request specific fixes with line references rather than abstract lessons. Use AI for evaluation and testing, not instruction delivery.
